# Vendly

Booking software for event vendors in Pakistan: photo booths, photographers, decorators, DJs, mehndi artists, caterers and makeup artists. Vendors take inquiries from a public booking page, send quotes, track advances and balances in rupees, run a checklist per event, and message clients through WhatsApp click-to-chat and automatic email.

Built from `Datebook build spec.md` and the Datebook design canvas (`Datebook.html`, `Datebook-png.zip`).

```
frontend/   Vite + React + TypeScript SPA      → Vercel
backend/    Node + Express + TypeScript API    → Vercel Functions (or Render)
            Postgres                            → Neon (free, doesn't expire)
render.yaml Render Blueprint for the API (alternative host)
```

## Run locally

Needs Node 20+. No local Postgres needed: without `DATABASE_URL` the API uses PGlite (Postgres in WASM) stored in `backend/.pglite`.

```bash
# terminal 1: API on :4000
cd backend
npm install
npm run dev

# terminal 2: web app on :5173 (proxies /api to :4000)
cd frontend
npm install
npm run dev

# optional: demo vendor with bookings, payments and inquiries
cd backend
API_URL=http://localhost:4000 ADMIN_SECRET=local node scripts/seed-demo.mjs
#   (start the API with ADMIN_SECRET=local so the demo gets the Team plan)
#   sign in: demo@vendly.pk / demo12345
```

Tests for the money and date rules (advance rounding, balance, refunds, Pakistani number grouping, Asia/Karachi dates, reschedule window, seasons, WhatsApp numbers):

```bash
cd backend && npm test
```

## Deploy

Order: database (Neon) → backend (Vercel, or Render) → frontend (Vercel). Everything below fits in the free tiers.

### 1. Database on Neon

1. Sign up at [neon.tech](https://neon.tech) (GitHub sign-in works) → **New project**.
   - Name: `vendly`. Postgres version: latest. Region: **AWS Asia Pacific (Singapore)**, the closest to Pakistan and to the Render API.
2. On the project dashboard click **Connect**.
3. Copy the connection string (the default shown, pooled, is fine). It looks like:
   ```
   postgresql://neondb_owner:xxxxxxxx@ep-cool-name-123456-pooler.ap-southeast-1.aws.neon.tech/neondb?sslmode=require&channel_binding=require
   ```
   Keep it private: it contains the database password.

Nothing else to do on Neon: the API creates its tables on first start.

Neon's free plan has 1 GB of storage per project and pauses the database after 5 idle minutes. The next query wakes it in about a second, and the API is set up for that (short connection timeouts, idle connections closed before Neon drops them).

### 2a. Backend on Vercel (free, no card)

`backend/vercel.json` and `backend/api/index.js` make the API run as a Vercel Function in Singapore (`sin1`). `npm run build` compiles `src/` to `dist/`, and every request is rewritten to the function, which is the Express app.

1. Vercel → **Add New → Project** → import the repo → click **Import single project** next to the backend (or Edit → Root Directory `backend`). Framework preset: **Other**.
2. Environment variables (Production and Preview): `DATABASE_URL` (Neon), `FRONTEND_URL` (your frontend's Vercel URL), `JWT_SECRET`, `CRON_SECRET`, `ADMIN_SECRET` (long random strings, e.g. `openssl rand -base64 36`), `IN_PROCESS_CRON=off`, optionally `RESEND_API_KEY`, `EMAIL_FROM_ADDRESS`, `GOOGLE_CLIENT_ID`, `FREE_BOOKINGS_PER_MONTH`, `PRO_PRICE`, `TEAM_PRICE`.
3. Deploy, then open `https://<backend>.vercel.app/api/health`.

Vercel's Hobby plan is for non-commercial use; move to Pro (or to Render below) once vendors pay. Hobby cron jobs run once a day, so use the external 15-minute cron described in **Scheduled emails**.

### 2b. Backend on Render (alternative)

1. Render dashboard → **New → Blueprint** → connect GitHub and pick the repo. Render reads `render.yaml` and creates `vendly-api` (root `backend/`, build `npm ci --include=dev && npm run build`, start `npm start`, health check `/api/health`, region Singapore, free plan).
2. Fill the variables marked *sync: false* when asked:
   - `DATABASE_URL` — the Neon connection string from step 1
   - `FRONTEND_URL` — your Vercel URL, e.g. `https://vendly.vercel.app`. You don't have it yet on a first deploy: put `http://localhost:5173` for now and change it after step 3. Vercel preview URLs of the same project are allowed automatically.
   - `RESEND_API_KEY`, `EMAIL_FROM_ADDRESS` — optional, for automatic email (see below)
   - `GOOGLE_CLIENT_ID` — optional, for Google sign-in
3. `JWT_SECRET`, `CRON_SECRET` and `ADMIN_SECRET` are generated by Render (find them later under the service → **Environment**).
4. When the deploy finishes, note the API URL, e.g. `https://vendly-api.onrender.com`, and open `https://vendly-api.onrender.com/api/health`. It should show `{"ok":true}`. The logs should show `[db] migrated 001_init.sql` on the first start.

> The free web service sleeps after 15 minutes without traffic, so the first request after a sleep takes about a minute. The cron ping in **Scheduled emails** below keeps it awake.

### 3. Frontend on Vercel

1. Vercel → **Add New → Project** → import the same repo.
2. Set **Root Directory** to `frontend`. Framework preset: Vite (also set in `frontend/vercel.json`).
3. Environment variable: `VITE_API_URL` = your Render API URL, no trailing slash (e.g. `https://vendly-api.onrender.com`).
4. Deploy. `vercel.json` sends every route to `index.html`, so links like `/b/yourstudio`, `/q/<token>` and `/r/<token>` work.
5. Copy your Vercel URL (e.g. `https://vendly.vercel.app`), go back to Render → `vendly-api` → **Environment**, set `FRONTEND_URL` to it and save (Render redeploys). It controls CORS and the links in emails and WhatsApp messages; until it's set, the app can't reach the API.

### Scheduled emails

Reminders, "Tomorrow at a glance", "Advance still missing", thank-you emails and moving finished bookings to Completed run from one job every 15 minutes (Asia/Karachi time). The API runs it in-process, but a sleeping free instance can't. Point any free external cron (for example cron-job.org) at:

```
POST https://<your-api>/api/cron/run
Header: x-cron-secret: <CRON_SECRET>
Every 15 minutes
```

On Render this also keeps the free instance awake. Running it more often is safe: `email_log` stops duplicate sends.

### Automatic email (Resend)

1. Create a Resend account, add and verify your sending domain (SPF, DKIM and DMARC records).
2. Set `RESEND_API_KEY` and `EMAIL_FROM_ADDRESS` (e.g. `bookings@yourdomain.pk`) on Render.
3. Emails go out as "<Business name> via Vendly" with Reply-To set to the vendor's email. Without a key, emails are only logged.

### Google sign-in (optional)

Google Cloud Console → Credentials → OAuth client ID (Web). Add your Vercel URL and `http://localhost:5173` under *Authorised JavaScript origins*, then set `GOOGLE_CLIENT_ID` on Render. The button appears only when it is set.

### Admin panel

People listed in `PLATFORM_ADMIN_EMAILS` (comma-separated, on the backend) get an **Admin** button in the app header. `/admin` shows every vendor that signed up, their bookings and inquiries, when they joined and were last active, and lets you change each vendor's plan. An admin can also be a normal vendor owner with their own business.

### Plans

Free plan: `FREE_BOOKINGS_PER_MONTH` bookings a month (default 10). Prices come from `PRO_PRICE` / `TEAM_PRICE`. Subscription payments are not built yet (spec build step 12), so plans are switched by hand in the admin panel, or with the `ADMIN_SECRET`:

```bash
curl -X POST https://<your-api>.onrender.com/api/admin/plan \
  -H "x-admin-secret: <ADMIN_SECRET>" -H "Content-Type: application/json" \
  -d '{"handle":"yourstudio","plan":"pro"}'
```

## How it maps to the spec

- **Roles**: owner, manager, event staff. Every query is filtered by the member's `business_id` in the API (`backend/src/auth.ts`); staff only get bookings they're assigned to and never receive money fields.
- **Money**: whole rupees in integers; advance = round(total × advance_pct ÷ 100), copied onto each booking; balance = max(0, total − paid); payments can't exceed the balance; refunds are negative payments; receipt numbers per business (`YS-0001`) with 32-character random link tokens. See `backend/src/lib/money.ts`.
- **Clash check**: a date is full when non-cancelled bookings reach `capacity_per_date`; pencilled-in inquiries stop counting once their quote's hold date passes. New booking, Accept and the booking page all check it; the vendor can override.
- **Dates**: stored as `date`/`time`, computed in Asia/Karachi (`backend/src/lib/dates.ts`).
- **WhatsApp**: `wa.me` click-to-chat with text from editable templates; numbers shown as copyable text too.
- **Dark mode**: follows the device by default; Settings → Appearance saves Light / Dark / Match phone per user. Client pages follow the client's device; emails are always light.

## Open decisions (from the spec)

- Product name: the UI says **Vendly**. Change `APP_NAME` on Render and the strings in `frontend/` if you pick another.
- Pro/Team prices and the Free limit are placeholders (`PRO_PRICE`, `TEAM_PRICE`, `FREE_BOOKINGS_PER_MONTH`).
- Booking page domain: links use your Vercel domain (`/b/<handle>`). Add a custom domain in Vercel when ready.
- Excel import accepts CSV with columns: date, client, phone, function, venue, total, paid.
